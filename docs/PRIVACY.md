# Data Rights and Privacy

## Public-suite rule

The public repository accepts:

- controlled canonical prompts written for this project;
- synthetic naturalistic prompts labeled as synthetic;
- structurally transformed real-derived prompts only after rights and privacy
  review.

It does not accept copied private chats or raw product logs.

## Real or real-derived data

Before a real-derived sample can be used, maintainers must record:

1. the right to use and publish the material;
2. the source and collection context;
3. the de-identification method;
4. a privacy and secrets review;
5. whether the message can be public, private, or restricted;
6. whether transformation changed the task meaning.

Verbatim raw messages belong only in a restricted evaluation store, not this
public Git repository.

## Prohibited data

Do not submit:

- credentials, tokens, private keys, or internal URLs;
- direct contact, account, payment, or government identifiers;
- private customer, employee, student, patient, or legal records;
- confidential business information;
- content whose license or publication rights are unknown.

Redaction alone is not sufficient if the remaining combination can identify a
person or organization.

## Honest source labels

Synthetic prose must never be described as sampled user behavior. If an
authentic block cannot be acquired safely, mark that coverage cell incomplete
instead of inventing provenance.

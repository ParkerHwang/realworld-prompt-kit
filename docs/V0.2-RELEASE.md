# v0.2 Artifact Core Release

Released: 2026-07-31
Status: `calibration_release`

v0.2 adds a portable benchmark track for ordinary file-grounded office work.
It complements the v0.1 text-only breadth track; it does not replace or alter
the 880 v0.1 semantic scenarios.

## What is included

| Surface | Count |
| --- | ---: |
| Semantic work episodes | 12 |
| Korean/English canonical/naturalistic realizations | 48 |
| Attached source files | 20 |
| Editable or machine-readable reference outputs | 18 |
| Work modules | 6 |
| Workflow jobs represented | 8 |

The episodes cover:

- attached-file grounding;
- document creation and revision;
- presentation creation and revision;
- spreadsheet creation and repair;
- cross-artifact repurposing and packaging;
- artifact audit, source checking, and controlled delivery.

Inputs include PDF, DOCX, PPTX, XLSX, CSV, and TXT. Required outputs include
DOCX, PPTX, XLSX, and one JSON package manifest. All fixtures are synthetic,
project-authored, hash-pinned, and declared free of personal data.

## Evaluation contract

Every scenario declares:

- the workplace goal and workflow job;
- exact attachments and their authority/trust roles;
- four paired request realizations;
- required output filenames, media types, editability, and side-effect scope;
- non-compensable hard gates;
- atomic rubric items linked to source or output evidence;
- executable check status and human-calibration status.

The validator checks schemas, counts, IDs, attachment references, path
boundaries, SHA-256 hashes, file parseability, native editability features,
output bundles, deterministic rubric checks, and the checked-in references.
The grader evaluates a submission against task properties rather than requiring
byte equality with one reference file.

## Run the release

```bash
python3 tools/validate.py --manifest data/v0.2/manifest.json
python3 tools/artifacts/coverage_report.py
python3 tools/artifacts/export_jsonl.py
python3 -m unittest discover -s tests
```

Grade one submission:

```bash
python3 tools/artifacts/grade_artifacts.py \
  --scenario data/v0.2/scenarios/<scenario_id>.json \
  --submission-dir /path/to/submission
```

Render a submission for manual review:

```bash
python3 tools/artifacts/render_artifacts.py \
  --scenario data/v0.2/scenarios/<scenario_id>.json \
  --artifact-dir /path/to/submission \
  --output-dir /path/to/previews
```

## Claim boundary

The checked-in reference outputs pass deterministic conformance and content
checks. That supports the claim that the public episodes, schemas, files, and
reference grader are runnable as a portable artifact-construction calibration
suite.

The following claims are explicitly unsupported in v0.2:

- a global ranking of office-worker capability;
- population-level task-frequency coverage;
- completed human practitioner calibration;
- externally replicated benchmark validity;
- GUI-operation proficiency;
- stateful safety for email, calendar, CRM, or shared-drive actions.

No aggregate leaderboard should be published from v0.2 without first
completing blind practitioner review, grader agreement studies, Korean/English
calibration, and independent reproduction.

## Rebuild

Release assets are generated from checked-in source builders:

```bash
python3 tools/artifacts/build_release.py --phase prepare
node tools/artifacts/build_office_assets.mjs
python3 tools/artifacts/build_release.py --phase finalize
```

The build normalizes archive metadata and asset hashes so a clean rebuild is
deterministic in the supported runtime. Rendering is a QA surface and is kept
out of the release data tree.
